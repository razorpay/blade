Blade Svelte (cx) vs Blade React - API Differences

src-cx vs packages/blade source: packages/blade-svelte/API-PARITY.md

1 The ten rules

Most differences are ten rules applied everywhere; learn them and most of cx's API follows from React's. The cx component set is @razorpay/blade-svelte/components.

1.1 Layout and composition

1 Layout goes through class

No Box, no styled props (margin, padding, width, maxWidth, display…). Every component takes a root class of Uno (Tailwind-style) classes. *-blade-N is Blade spacing token N (0–11); other lengths use brackets (w-[176px]).

Effect: one layout language; props cover only what the component decides.

2 Render props and sub-components become snippets

AccordionItemHeader, ActionListItemAsset, header leading / trailing / titleSuffix and footers become Svelte snippets, where the caller renders Text, Icon, Badge directly. Snippets that close their surface receive { close }. Props remain only where behaviour or accessibility need them, e.g. a title naming a tooltip.

Collections compose: items (CardGroupItem, ActionListItem, TabItem, Chip…) register with their parent in document order, so headings or dividers can sit between. Data plus an item snippet only where every item must be known up front: VirtualOptionList, Carousel.

1.2 State and events

3 No default* props: state is bindable

defaultValue, defaultChecked, defaultCountry, defaultExpandedIndex, defaultIsOpen… fold into the bindable prop: uncontrolled is bind:value with an initial value; controlled is a value the host keeps driving.

<!-- React -->
<TextInput defaultValue="Asha" />
<!-- cx -->
<TextInput bind:value={name} />

4 Callbacks keep Blade's payloads, without event

Fields report onChange({ name, value }), Checkbox { isChecked, value }, Switch { isChecked }, ChipGroup { name, values }, OTPInput onOTPFilled({ name, value }). No event: callers get values, not DOM objects. Where React passes a bare value, so does cx (Tabs, Carousel).

Overlays: Tooltip reports onOpenChange({ isOpen }).

1.3 Fields and inputs

5 label is a plain string

label is a string on every field: it names the control. React's labelSuffix and labelTrailing are not ported; nothing sits beside the label. Hint lines (helpText, errorText, successText) take string | Snippet, e.g. for a link.

6 Web names for keyboards and autofill

HTML names replace React Native's: type="tel" (not telephone), inputMode, enterKeyHint (for keyboardReturnKeyType), autoComplete (for autoCompleteSuggestionType), autoCapitalize. Each type keeps Blade's defaults; number renders as type="text". Search and password fields are their own components over TextInput.

1.4 Theming, icons, defaults

7 BladeProvider sets component defaults, not a theme

Theming stays CSS variables; themeTokens and colorScheme are not ported. The provider takes an overall size every sized control snaps to, per-component defaults for any style prop, and adapters. Nothing reads the viewport in JS: components are mobile first and their desktop differences are d: classes (one breakpoint, 62.5rem). A prop wins, then the nearest provider's entry for the component, then its overall size, then Blade's default.

Colour: cx uses Blade's neutral theme, where "primary" text is black; Figma's blue primary is the standard theme.

8 Icons are data, not components

React's ~450 *Icon components become 450 same-named SVG exports in @razorpay/blade-svelte/icons, as Svelte cannot pass an instantiated component (React's <InfoIcon />) as a value. Draw one with <Icon source={…} /> or pass it to a component's icon or slot. The build plugin (bladePlugin from @razorpay/blade-svelte/configs/vite or /configs/webpack) turns an app's imported icons into one font; without it they render as CSS masks. Icons are single-colour and take their host's colour.

A slot named by position (leading, trailing) takes an icon, drawn as the component's sized, tinted glyph, or a snippet, placed in the asset box — one or the other. icon exists only for a single glyph with no slot: Button, Link, IconButton, Badge, Alert, Avatar, BreadcrumbItem, AnnouncementBanner, EmptyState's title glyph.

9 children is what you press, content what it reveals

Tooltip (and Collapsible, not exported yet) take the trigger as children, as in React. As a snippet it receives { isOpen }; the wrapper around it listens, so the trigger wires nothing. The revealed part is content.

10 Deferred

Safe to port later:

  • data-analytics-* props, pending an analytics pass.
  • labelPosition: labels sit above fields.

4 Figma over React

Where Blade DSL in Figma and React disagree, cx follows Figma:

  • Options cut to what Figma draws: Badge and TextInput xsmall, IconButton moderate, Button tertiary, Link notice / information.
  • Slots added where Figma draws them: Button and Link trailing icons, ActionListItem descriptions and suffixes.
  • Figma's tokens for ActionList row text, icons and the keyboard ring.
  • Measurements: Avatar rim, Code's 14/18 lines, Display's letter-spacing, Breadcrumb's intense pills, Switch at one size on every width.

1 Tooltip: children and content, as in React

React clones handlers onto its single child. cx renders children inside a wrapper that listens for hover, focus and taps, so the trigger wires nothing; children({ isOpen }) reads the state. content is a string or a snippet.

1. A plain tooltip

<Tooltip
  title="Convenience fee"
  content="Charged by your bank"
>
  <Button variant="secondary">
    Why a fee?
  </Button>
</Tooltip>
  • Identical markup in both.
  • Hover opens after a short rest and closes after a short grace, so the pointer can reach the bubble. Focus opens at once. A tap toggles; the only way in on touch and native.
  • Escape closes only the tooltip, not an overlay beneath it.
  • While open, the bubble describes the trigger's first focusable element (aria-describedby).

2. A trigger that is not a control

<Tooltip content="Set by your bank">
  <IconButton
    icon={InfoIcon}
    accessibilityLabel="Fee details"
  />
</Tooltip>

React's TooltipInteractiveWrapper is an inline-block div carrying the ref and handlers a non-interactive child (icon, Badge, Counter) can't. cx's wrapper is always there: hover and taps reach anything inside, but the keyboard reaches only focusable content, so use a button or link.

3. Rich content: content and title as snippets

<Tooltip>
  <Button variant="secondary">
    Settlement
  </Button>
  {#snippet title()}
    Settles in <b>T+2</b>
  {/snippet}
  {#snippet content()}
    Weekends and bank holidays
    excluded.
  {/snippet}
</Tooltip>

React takes strings only. A cx snippet sits in its box and inherits its type.

4. Reading and blocking the open state

<Tooltip
  content="Copied"
  isDisabled={!hasCopied}
  onOpenChange={({ isOpen }) =>
    track(isOpen)}
>
  {#snippet children({ isOpen })}
    <IconButton
      icon={CopyIcon}
      accessibilityLabel="Copy"
      isHighlighted={isOpen}
    />
  {/snippet}
</Tooltip>

onOpenChange({ isOpen }) matches React. isDisabled (cx only) never opens, and closes if open. No isOpen prop; the tooltip owns its state.

5. Placement

Both default to top. React excludes left-start, left-end, right-start and right-end; cx accepts all twelve. On web the bubble renders in the OverlayStack, flips when short of room and clamps on the cross axis, arrow kept on the trigger. On native it sits in the wrapper at the requested placement, unmeasured.

2 ActionList: row parts as props and snippets

ActionList is OptionList, designed. OptionList is the headless list (value, keyboard, form field, search, sections); ActionList is its look (variant) and its rows (ActionListItem). Use it on a page, composed or over data (virtualizedItems, virtualizedSections). PhoneNumberInput's country picker is the last: ActionListItem rows searched through the list's query.

React fills ActionListItem slots with wrappers (ActionListItemIcon, ActionListItemAsset, ActionListItemAvatar, ActionListItemBadge, ActionListItemText). cx has none: leading takes an icon or a snippet; titleSuffix and trailing are snippets the row sizes and places.

  • With selectionType="multiple", the checkbox comes first.
  • React's description keeps its name: the muted line under the title.

4 Hint lines: strings or snippets

helpText, errorText and successText are strings in React, string | Snippet in cx (TextInput, PasswordInput, PhoneNumberInput, TextArea, OTPInput, InputGroup). The state's own text shows, else helpText. CounterInput has no hint line in either.

1. Plain text: the same in both

<TextInput
  label="UPI ID"
  bind:value={upi}
  validationState={state}
  helpText="e.g. name@okaxis"
  errorText="Enter a valid UPI ID"
  successText="Verified"
/>

React uses value + onChange for bind:value. Error and success lines lead with their icon (12px, 16px at large) in both.

2. A line with a link in it

React
// helpText is a string: the link
// goes outside the field.
<TextInput
  label="GSTIN"
  helpText="Forgot it?"
/>
<Link href="/gstin" size="small">
  Find your GSTIN
</Link>
cx
<TextInput label="GSTIN">
  {#snippet helpText()}
    Forgot it?
    <Link href="/gstin" size="small">
      Find your GSTIN
    </Link>
  {/snippet}
</TextInput>
  • The snippet takes the hint's text style and colour, under the control; aria-describedby still points at it.
  • An errorText snippet (e.g. “Wrong password. Reset it”) still gets the field's error icon before it.
  • Strings and snippets mix: a string helpText with a snippet errorText is fine.

3. Inside a Form: leave out validationState

<Form name="login" onSubmit={submit}>
  <TextInput
    label="Email"
    name="email"
    type="email"
    isRequired
    helpText="We send the receipt here"
  />
</Form>

Without validationState the field shows its form error once touched or after a submit attempt, replacing the line. Pass validationState to own the state. React has no form context.

  • sections ({ key, title, items }) in place of items: each heading is a row of its own, scrolled with the rest, under one window; the keyboard runs across sections as one list.
  • Opens scrolled to its pick and stays one tab stop: if the pick is beyond the slice, the first enabled row in view holds it. Home, End, PageUp, PageDown scroll to mount the row they reach.
  • Otherwise OptionList's field contract: name, isRequired, selectionType (multiple, none), validationState, hint lines, query / match / empty.
